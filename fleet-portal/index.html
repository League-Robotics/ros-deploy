ROS Fleet Connection Portal

Everything an agent needs to reach the robots — no usernames or passwords required.

You (an agent on this network) can connect to the ROS fleet without knowing any login name or password. This page hands you a pre-authorized SSH key and a set of host aliases; the ROS side is reached over WebSocket gateways that need no credentials at all. Everything is served from {{BASE_URL}}.

Quickest path — one command

Run this on the machine you want to connect from. It fetches the fleet key, installs SSH aliases, and leaves you able to ssh agony (and the rest) with no further input:

curl -fsSL {{BASE_URL}}/connect.sh | sh

Then: ssh agony hostname — you're in as the shared {{SSH_USER}} account. You never typed a username or password.

How access works (so you know what you're holding)

SSH

You authenticate with the key this portal gives you, logging in as the shared {{SSH_USER}} account. The username and key path live inside the SSH config alias, so you just run ssh agony — no password is ever entered.

ROS

The gateway hosts expose rosbridge at ws://<host>:9090. It requires no ROS credentials whatsoever — open a WebSocket and you can publish and subscribe to any topic. Use roslibpy (Python) or roslib.js (browser).

Manual setup (if you'd rather not pipe to a shell)

1

Get the key. This is the one secret — it authorizes the shared {{SSH_USER}} account on every node.

curl -fsSL {{BASE_URL}}/keys/fleet_id -o ~/.ssh/fleet_id
chmod 600 ~/.ssh/fleet_id
2

Install the host aliases. This block pre-fills user + key for every host, so you never supply either by hand.

curl -fsSL {{BASE_URL}}/ssh_config -o ~/.ssh/fleet_config
grep -q 'Include ~/.ssh/fleet_config' ~/.ssh/config 2>/dev/null \
  || sed -i '1i Include ~/.ssh/fleet_config' ~/.ssh/config 2>/dev/null \
  || echo 'Include ~/.ssh/fleet_config' >> ~/.ssh/config
3

Connect.

ssh agony     # or torture, ali, nepr, vidar
ssh vidar 'ros2 topic list'

Running ros2 commands over SSH

If you SSH in and run ros2, you must set the domain ID and source ROS yourself — a non-interactive SSH session does not inherit them, so without this ros2 silently talks to domain 0 and sees an empty fleet:

ssh agony 'ROS_DOMAIN_ID={{ROS_DOMAIN_ID}} bash -lc "source /opt/ros/*/setup.bash && ros2 topic list"'

Talking to ROS without the ROS stack

If you can't (or don't want to) install ROS, use the rosbridge gateways. Example with roslibpy:

pip install roslibpy
python3 - <<'PY'
import roslibpy
ros = roslibpy.Ros(host='agony', port=9090)   # no auth
ros.run()
print('topics:', ros.get_topics())
ros.terminate()
PY

The MJPEG camera streams on vidar are plain HTTP, no auth either: http://vidar:8080/.
